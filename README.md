# Radio Code DB: frontend

A static web app for searching car radio unlock-code datasets by **serial number, Renault/Dacia precode or VIN**. You enter the key only, with no brand. Every database is searched at once, and matches from different databases are shown together.

Live at: **https://db.radiocodeglobal.de** (Cloudflare Pages)

It's plain HTML, CSS and vanilla JavaScript, with **no build step**. The repo root is the site root.

```
index.html   page shell with three views: Search, Database browser, About the data
styles.css   all styling (responsive, CSS/SVG icons only, no photos or AI imagery)
app.js       the app logic; API_BASE is set at the top
favicon.svg  hand-written SVG icon
_headers     Cloudflare Pages security and caching headers (CSP allows the API origin)
```

## Views

1. **Search** (`#search?q=KEY`). One input box. It calls `GET /search?q=KEY`, with an optional *Prefix match* checkbox that adds `&mode=prefix`.
   - Every column of every matching row is shown. Columns differ by database, so they are rendered from each row's own keys.
   - **Cross-database matches:** results are grouped by the key they matched. If the same key exists in more than one database, the group is highlighted with a **"Found in N databases"** badge and shows one card per database side by side. The card is labelled with the database name, a code-status badge and an origin badge.
   - **Plain vs encoded:** Philips and Grundig rows (`code_status: unverified_encoded`) have an amber **"Encoded / unverified"** badge. Their `code_or_hex` value is shown struck through, with a note saying it is *not a usable radio code*. Plain codes are shown large in green. Rows from algorithm-generated tables get a "calculated by a public algorithm, not tested on this radio" note. All-zero codes are flagged as likely placeholders.
   - The view handles loading, input validation (3–40 letters or digits), *No match found* and API errors.
2. **Database browser** (`#browse?db=NAME&page=N&size=S`). A dropdown filled from `GET /databases`, showing the display name and row count. It shows a metadata panel (rows, key column, columns, origin, source link, notes, status) and a paginated table from `GET /browse`. You get First, Prev, Next and Last buttons, a jump-to-page box, a page-size selector (25, 50, 100 or 200), and the row range, total and total pages. Columns come from the API response.
3. **About the data** (`#about`). Totals plus one card for each database with all its metadata and caveats.

An API status indicator in the header checks `GET /health`. If the API can't be reached, a friendly banner appears and the app re-checks every 15 seconds. It reloads automatically once the API is back.

## API

The base URL is set in one constant at the top of `app.js`:

```js
const API_BASE = 'https://dbapi.radiocodeglobal.de';
```

| Endpoint | Returns |
|---|---|
| `GET /health` | `{ok:true}` |
| `GET /databases` | `[{name, display_name, row_count, columns, key_column, code_status, origin, source_url, notes}]` |
| `GET /search?q=KEY[&mode=prefix]` | `{ok, query, normalized, mode, total, returned, limit, databases_matched, results:[{database, display_name, code_status, origin, matched_key, row_id, ...columns}]}`. The key is normalized on the server (uppercased, spaces and dashes removed). If there is no exact match and the key is 5 characters or more, it falls back to prefix matching. Up to 200 results. |
| `GET /browse?db=NAME&page=N&pageSize=1-200` | `{ok, db, display_name, code_status, columns, page, pageSize, total, totalPages, rows}` |

The API is GET-only, public and sends `Access-Control-Allow-Origin: *`. The frontend holds no secrets.

## Data sources and caveats

| Database | Rows | Key | Status | Caveat |
|---|---:|---|---|---|
| `philips`: Philips OEM radios (CarProg `philips.dat`) | 16,079,038 | serial | **encoded / unverified** | Vendor file of unconfirmed origin. Serials are plain text, but the 3-byte value per record is stored as hex and **is not a decoded radio code**. The encoding is unknown. `brand_hint` is guessed from the serial prefix. |
| `grundig`: Grundig OEM radios (CarProg `grundig.dat`) | 2,955,331 | serial | **encoded / unverified** | Same as Philips. |
| `ford_m`: Ford M-series | 1,000,000 | serial | plain code | **Generated by an algorithm** for the full M000000–M999999 range. Not collected from or tested on real radios. |
| `ford_v`: Ford V-series | 1,000,000 | serial | plain code | Generated by an algorithm (DavidB445 `radiocodes.bin`). 78 entries read `0000` and are probably invalid. |
| `renault_precode`: Renault / Dacia precodes | 23,400 | precode | plain code | Generated with the public precode algorithm (letter + 3 digits). Many Dacia radios use the same scheme. |
| `vw_gist`: VW group serials | 500 | serial | plain code | Small public gist list. |
| `vw_vin_gist`: VW VIN + serial | 157 | vin / serial | plain code | Small public gist list (VWVortex). |

There are 21,058,426 rows in total. Coverage is partial: there is no free bulk data for BMW, Mercedes, Toyota, Hyundai/Kia and others. "Plain code" means the stored value is readable. It does **not** mean the code has been confirmed to unlock a radio. Use this only for radios you own or are authorised to service.

## Deploy on Cloudflare Pages

No build is needed.

1. Cloudflare dashboard → **Workers & Pages → Create → Pages → Connect to Git** → pick this repo.
2. Production branch: `main`. Framework preset: **None**. Build command: *(leave empty)*. Build output directory: `/`.
3. Deploy, then **Custom domains → Set up a custom domain → `db.radiocodeglobal.de`**. The zone must be on the same Cloudflare account. Pages creates the CNAME.

Or use the CLI: `npx wrangler pages deploy . --project-name radiocodedb-frontend --branch main`.

If the API moves, change `API_BASE` in `app.js` **and** the `connect-src` entry in `_headers`.
